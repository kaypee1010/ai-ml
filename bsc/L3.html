Searching, BFS & DFS

No maps, no signs, no shortcuts told to you — just a systematic way to explore. Click through the animations below to watch it happen.

📘 BSc Data Science · Non-Technical

Quick recap: Last time — an AI Technique organizes knowledge, and a Production System uses IF-THEN rule cards. But we ended on a cliffhanger: what if there's no rule card for the situation at all?

🏢 1. The Hostel With No Directory

🤖Here's today's problem...

You're visiting a friend in a large hostel. There's no directory, no signs, no Google Maps for the inside of a building. All you know is: you start at Reception, and somewhere ahead is your friend's room.

How do you explore, systematically, without wandering the same corridor twice?

🚶 2. Wandering Randomly Doesn't Work

The naive approach: just walk wherever feels right, turn randomly, hope for the best.

This breaks down fast — you might walk the same corridor three times, miss a wing entirely, or never even realize you're going in circles. There's no guarantee you'll ever find the room.

Felt need: a systematic method that guarantees you'll eventually explore everywhere, without repeating yourself.

🗺️ 3. Turning a Building Into a Diagram

Here's the trick AI uses: turn the problem into a simple diagram of dots and lines.

⚪ State

A "dot" — one possible situation you could be in (a junction, a room, a corridor end).

➖ Path / Action

A "line" connecting two dots — moving from one situation to the next (walking down a corridor).

This whole diagram is called a state space. Your Reception is the start state. Your friend's room is the goal state. Searching in AI simply means: systematically exploring this diagram until you reach the goal.

💭 4. Quick Check — Predict First

🤔Think before you scroll...

If you have zero extra clues (no signs, no map, nothing) — what's a systematic way you could still guarantee finding your friend eventually, given enough time?

Reveal answer
Explore every possible corridor and junction in some fixed, non-repeating order — check every path once. That "no extra clues, just explore systematically" idea is exactly what Uninformed Search means. (If you *did* have a clue — like "the room numbers get bigger this way" — that's a different family called Informed Search, for a future lecture.)
Uninformed Search = exploring the state space using only the start state and the rules of movement — no extra hints, no shortcuts, no "getting warmer" clues. Today we cover the two most basic uninformed strategies: BFS and DFS.

🌊 5. Breadth-First Search (BFS) — Explore Like Ripples

🌊Strategy 1...

Drop a stone in still water — the ripples spread out evenly, covering the nearest ring completely before reaching the next ring. BFS explores exactly like that: check everything one step away first, then everything two steps away, then three...

Breadth-First Search (BFS) — plain English: "explore level by level, nearest first." It keeps a waiting line of places-to-visit-next, always visiting the one that's been waiting longest. That waiting line is called a Queue (First In, First Out — FIFO): whoever joined the line first gets served first.

📲 7. BFS in Real Life

🔗 "Degrees of connection"

LinkedIn/Facebook showing "2nd-degree connections" — it checks your direct friends first, then their friends, ring by ring.

📨 Forward chains

Tracing how a WhatsApp forward spread — who got it first, then who they sent it to, level by level.

🕳️ 8. Depth-First Search (DFS) — Commit to One Path

🕳️Strategy 2 — the opposite idea...

Now imagine the opposite instinct: pick one corridor and follow it all the way to the end before trying anything else. Only when you hit a dead end do you turn back and try the next option.

Depth-First Search (DFS) — plain English: "commit fully to one path, backtrack only when stuck." Instead of a waiting line, it keeps a Stack (Last In, First Out — LIFO) — like a pile of plates: whichever option was added most recently gets tried next.

▶️ 9. Watch DFS Explore the Same Hostel

Same building, same goal — but a completely different strategy. Watch the Stack this time.

Notice: DFS commits to Wing A first and walks its entire dead-end corridor before ever trying Wing B — even though the goal was in Wing B the whole time. Same building, same goal, more steps.

📲 10. DFS in Real Life

📁 Folder drilling

Opening a folder, then its subfolder, then *its* subfolder — fully exploring one branch before checking a sibling folder.

🧩 Solving a maze by hand

Following one path with your finger until it's a dead end, then backtracking to the last junction.

⚖️ 11. BFS vs DFS — Side by Side

Both are uninformed — neither uses any clue about where the goal actually is. They just differ in the order they check things.
Common mix-up: Students often think DFS is "wrong" or "worse" because it took more steps in our example. It isn't — DFS is simply a different trade-off (lower memory use). Whether BFS or DFS is "better" always depends on the shape of the actual problem.
"BFS checks everywhere nearby before going far. DFS commits to one direction fully before trying another. Neither one 'looks ahead' — they just differ in the order they explore."

What is meant by "searching" in Artificial Intelligence?
Systematically exploring a state space (a diagram of possible situations connected by possible moves) starting from a start state, in order to reach a goal state.
Define state, start state, and goal state.
A state is one possible situation in the problem. The start state is where the search begins. The goal state is the situation the search is trying to reach.
What does "Uninformed Search" mean? Name two examples.
Search that uses no extra information about the problem beyond the start state and the rules of movement — no hints about how close the goal is. Examples: Breadth-First Search (BFS) and Depth-First Search (DFS).
Explain Breadth-First Search in your own words.
BFS explores level by level, checking everything one step away before anything two steps away, using a Queue (FIFO) to always visit whichever place has been waiting longest.
Explain Depth-First Search in your own words.
DFS commits fully to one path, going as deep as possible, and only backtracks to try another path once it hits a dead end. It uses a Stack (LIFO), always trying the most recently added option next.
Compare BFS and DFS on: (a) data structure used, (b) whether the shortest path is guaranteed, (c) memory usage.
(a) BFS uses a Queue, DFS uses a Stack. (b) BFS guarantees the shortest number of steps to the goal; DFS does not. (c) BFS can use more memory (wide waiting line); DFS generally uses less (only the current path is kept).
With the help of a diagram, trace BFS and DFS on a simple tree and show the order in which nodes are visited.
Using the hostel tree (S → A, B; A → A1 → A2 → A3; B → Goal): BFS visits S, A, B, A1, Goal (5 steps — checks both wings at each level before going deeper). DFS visits S, A, A1, A2, A3, B, Goal (7 steps — fully exhausts Wing A first). See the animated diagrams above for the full step-by-step trace.

🔁 Quick Recap

  • Searching = exploring a state space (dots = states, lines = moves) from a start state to a goal state.
  • Uninformed search = no extra clues, just a systematic order of exploring.
  • BFS = level by level, using a Queue (FIFO) — guarantees the shortest path, but can use more memory.
  • DFS = commit to one path fully, using a Stack (LIFO) — lower memory, but no shortest-path guarantee.
🎉Looking ahead:
Both BFS and DFS search "blindly" — no clue about which direction is actually closer to the goal. What if the search could use a smart hint, like "the room numbers get bigger this way," to skip the wrong turns entirely? That family of strategies is called Informed Search — a story for a future lecture.
